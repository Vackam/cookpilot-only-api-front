# feat/cook-session-one-control-layout

## 문제 상황

조리 중 화면에서 가장 중요한 것은 조리 사진이다. 그다음이 설명 자막, 음성 입력, 타이머 순이다.
지금 화면은 그 순서가 화면에 드러나지 않는다.

- 사진은 스크롤 목록 한가운데의 210px 카드다. 화면의 4분의 1도 못 쓴다.
- 화면에서 가장 무거운 것은 검은 타이머 카드다(패딩 20 + 44pt 숫자 + 버튼 3개). 4순위가 1순위보다 크다.
- 음성 버튼은 아래로 밀려 있어 800x600 화면에서는 아예 만들어지지도 않는다(기존 테스트가 전부 `ensureVisible`로 스크롤해서 누른다).

`refactor/design-token-layer`로 색·타이포·밀도는 화면 밖으로 뺐지만, **배치는 여전히
`_CookSessionScreenState` 1,660줄 안에 박혀 있어** 대안 배치를 붙일 자리가 없었다.
그 문서가 "레이아웃 변주가 필요해지면 그때 B(화면별 분리)를 화면 하나씩" 이라고 미뤄 둔 지점이다.

## 검토한 대안

배치 후보 5안을 그려 비교했다(A 풀블리드 자막 / B 6:4 데크 / C 원 컨트롤 / D 스텝 캐러셀 /
E 핸즈프리 자막 우선). 그중 C를 구현했다.

배치를 갈아끼우는 방법은 셋을 놓고 골랐다.

| 안 | 얻는 것 | 비용 |
|---|---|---|
| 1. C로 화면을 그냥 교체 | 가장 적은 코드 | 기존 위젯 테스트 8개가 깨진다. 되돌리려면 다시 뜯어야 한다 |
| 2. 뷰모델 + 배치 인터페이스 (채택) | 배치를 실기기에서 눌러 비교. 상태는 손대지 않음 | 파일 5개, 뷰모델 필드 30개 |
| 3. 헤드리스 컨트롤러로 상태까지 분리 | 배치가 상태 클래스를 아예 모름 | 1,660줄 이동. 지금 목적(배치 비교)에 필요 없다 |

3번을 하지 않은 이유가 중요하다. **지금 바꾸고 싶은 것은 배치뿐**이고, 상태는 옮기지 않아도
배치를 갈아끼울 수 있다. 타이머·STT·코치·저장 로직은 한 줄도 이동하지 않았다.

## 최종 결정

### 구조

```
lib/features/mvp/cook_layouts/
  cook_session_view_model.dart   # 값 + 콜백. 배치가 보는 유일한 입력
  cook_layout.dart               # abstract: Widget build(context, vm)
  cook_layout_catalog.dart       # 배치 목록 + 기본값 + 디버그 전환 상태
  cook_layout_switcher.dart      # 디버그 전용 배치 순환 손잡이
  layout_classic.dart            # 기존 배치(기준선)
  layout_one_control.dart        # C안
```

`_CookSessionScreenState.build()`는 이제 뷰모델을 조립하고 배치에 넘기기만 한다(320줄 → 60줄).

`cooking/presentation/`이 아니라 `mvp/` 아래에 둔 이유: 배치는 `mvp/mvp_widgets.dart`의
`FoodImage`·`PressableScale`을 쓴다. `cooking/` 아래에 두면 `mvp/`가 `cooking/`을 부르고
`cooking/`이 다시 `mvp/`를 부르는 순환이 생긴다.

### C안 — 원 컨트롤

사진을 화면 전체로 깔고 조작을 가운데 원 하나로 모았다.

- **원**: 안쪽은 마이크, 둘레 링은 남은 시간. 탭하면 말하기, 길게 누르면 타이머.
  3순위(음성)와 4순위(타이머)를 한 자리에 겹쳐 1순위(사진)에 면적을 내줬다.
- **자막 카드**: 조작 원 바로 위. 4줄에서 잘리고 누르면 전문을 시트로 펼친다.
- **직접 입력 / AI 코치**: 앱바에 38px 원형 버튼 두 개. 시트에 숨기지 않은 이유는
  숨기면 있는 줄 모르기 때문이고, 원으로 둔 이유는 사진을 거의 먹지 않기 때문이다.
- **1분 추가 / 리셋**: 원에 겹칠 수 없어 아래 텍스트 버튼으로 내렸다. 무게를 최대한 뺐다.
- 안내(고지·오류·도움 답변·코치 상태)는 자막 카드 위에 쌓이고, 사진 높이의 62%를 넘기면
  스크롤된다. `reverse: true`라 늘어나도 자막 카드는 늘 조작 원 바로 위에 남는다.

### 기본 배치는 그대로 둔다

`defaultCookLayout`은 `ClassicCookLayout`이다. C를 기본으로 올리면 `다음 단계` FilledButton,
`직접 입력` 라벨, `1분 추가`/`리셋` 버튼을 찾는 기존 위젯 테스트 8개가 깨진다.
승자가 정해지기 전까지는 기준선을 기본으로 두고, C는 디버그 전환 손잡이로만 띄운다.

### 새 토큰 `cookControlSize` 하나

원 컨트롤 지름은 기존 토큰 어디에도 없었다. `refactor-design-token-layer.md`의 규칙대로
화면에 리터럴을 두지 않고 `DesignDensity`에 토큰을 추가하고 네 안 모두에 값을 채웠다
(warm/midnight 96, crisp 88, roomy 112).

### 배치 계약을 테스트가 지킨다

`test/features/mvp/cook_layouts/cook_layout_test.dart`가 카탈로그의 **모든** 배치를 돌며
`voice-input-toggle`·`voice-input-status`·`help-request`·`coach-toggle`·`ai-data-disclosure`
키와 `n / m 단계`·`다음 단계` 문구를 확인한다. 새 배치가 하나라도 빠뜨리면 조리 화면
위젯 테스트가 아니라 여기서 먼저 걸린다.

## 검증

- `dart format --set-exit-if-changed` 통과
- `flutter analyze` 경고 0
- `flutter test` 406개 통과 (기존 398 + 신규 8). **기존 테스트는 한 줄도 고치지 않았다.**
- 신규 테스트가 지키는 것
  - 카탈로그의 모든 배치가 위 계약 키·문구를 노출한다
  - 배치 id가 겹치지 않고, 기본 배치가 카탈로그에 들어 있다
  - 원을 탭하면 말하기가, 길게 누르면 타이머가 움직인다(서로 섞이지 않는다)
  - 남은 시간이 조작 원 안에 나온다
  - 안내 세 개(오류·도움 답변·코치 상태)가 한꺼번에 떠도 375x667에서 넘치지 않는다
  - 자막을 누르면 전문 시트가 열린다

## 이후 작업에서 지킬 것

1. **배치는 뷰모델만 보고 그린다.** 배치 파일에서 `widget.recipe`나 `setState`를 부르지 않는다.
   새 값이 필요하면 `CookSessionViewModel`에 필드를 더한다.
2. **새 배치를 추가하면 `cook_layout_catalog.dart`에만 넣는다.** 화면 상태 클래스는 손대지 않는다.
   계약 테스트가 자동으로 새 배치를 검사한다.
3. **기본 배치를 바꾸는 것은 별도 작업이다.** 위젯 테스트 8개의 기대 문구를 함께 고쳐야 한다.

## 남은 것 / 알려진 차이

- **사진 위 글자색 토큰이 없다.** C안은 스크림 위 글자에 `onInverse`를 쓴다. 이 앱이 사진
  스크림 위 글자에 이미 쓰고 있는 색이라 따랐지만(`mvp_widgets.dart`의 레시피 카드),
  어두운 안(`midnight-prep`)에서는 `onInverse`가 어두운 색이라 어두운 스크림 위에서 대비가
  무너진다. 기존에도 있던 문제이고 C안이 그것을 가장 크게 드러낸다. 고치려면 `onScrim` /
  `onScrimMuted` 토큰을 `DesignPalette`에 추가해야 하는데, 디자인 시스템 변경이라 이번
  작업에 섞지 않았다.
- **길게 눌러 타이머는 배워야 아는 동작이다.** 힌트 문구를 조작 원 아래 상시 노출했지만,
  실기기에서 실제로 발견되는지는 확인하지 못했다.
- 나머지 4안(A·B·D·E)은 구현하지 않았다. 뼈대가 같아서 배치 파일 하나씩만 추가하면 된다.
- 현재 브랜치가 `main`이라 커밋하지 않았다. AGENTS.md에 따라
  `feat/cook-session-one-control-layout` 브랜치를 만들어 PR로 올릴 것.
