# feat/recipe-tags-display — 레시피 태그를 칩으로 보여준다 (서버 전 임시 파싱)

## 문제 상황

레시피 태그(조리방법·요리종류·해시태그)가 서버에서 별도 필드로 오지 않고 `description`
문자열 안에 줄바꿈으로 이어 붙어 온다.

```
월계수잎과 통후추 등을 사용해 ... 만들었어요.
조리방법: 굽기 | 요리종류: 반찬
1인분 310.8kcal · 탄수화물 9.4g · ...
해시태그: 저염간장
```

- 레시피 상세는 이 네 줄을 `Text` 하나로 그대로 뿌려서, 설명 밑에 태그와 영양 정보가
  문단처럼 붙어 보인다.
- 목록·검색 타일은 `maxLines: 1`이라 첫 줄만 살아남는다. 태그는 잘려서 버려진다.

서버에 컬럼 분리를 요청했지만(요청 스펙은 백엔드 저장소로 넘김) 배포 전까지는 이 상태다.

## 검토한 대안

- **서버 나올 때까지 그대로 둔다** — 상세 화면의 텍스트 덩어리가 계속 남는다. 기각.
- **화면마다 문자열을 잘라 쓴다** — 같은 포맷 지식이 여러 위젯에 복제된다. 기각.
- **domain에 파서 하나를 두고 화면은 결과만 쓴다(채택)** — 서버가 필드를 열면 파서 파일
  하나만 지우면 된다.

## 최종 결정

### 1. `RecipeTags.parse`는 domain에 한 곳만

`lib/features/recipe/domain/recipe_tags.dart`. Flutter 무의존 순수 Dart.
`description`을 줄 단위로 훑어 `조리방법: X | 요리종류: Y` 줄과 `해시태그: ...` 줄만
걷어내고, 나머지를 `body`로 돌려준다.

**영양 정보 줄은 건드리지 않는다.** 태그로 뺄 계획이 없어서 `body`에 그대로 남는다 —
지우면 화면에서 정보가 사라진다.

파일 맨 위에 임시 파서라는 것과 지울 조건을 적어 뒀다. 칩이 안 보이면 여기부터 본다.

### 2. 칩은 조용한 변형을 새로 만든다

`TagChip`(wash 배경 + line 테두리 + slate 글자). 기존 `ImageLabelChip`은 포인트 색이라
한 화면에 하나 놓을 때 쓰는 것이고, 태그는 개수가 많아 그 색으로 깔면 제목을 이긴다.

칩 순서는 요리종류 → 조리방법 → 해시태그. 분류가 앞이다.

### 3. 화면별 적용

- **레시피 상세**: 설명(`body`) 아래 `Wrap`으로 칩을 깐다. `body`가 비면 텍스트 자리를
  아예 안 만든다.
- **목록·검색 타일**: `subtitle`을 `body`로 바꾼다. 한 줄만 보이는 자리라 칩은 넣지 않고,
  태그 줄에 설명이 밀리던 것만 정리했다.

## 검증

- `recipe_tags_test` — 실서버 전수 조사(1,150건)에서 확인한 줄 구조 4가지를 모두 고정:
  4줄(설명·태그·영양·해시태그), 3줄(해시태그 없음), 2줄(설명 본문 없음), 1줄(구 MVP 시드).
  `국&찌개`처럼 `&`가 든 값, 쉼표·공백 혼용 해시태그, 빈 문자열도 포함.
- `dart format --set-exit-if-changed .` / `flutter analyze` 0건 / `flutter test` 443개 통과

## 이후 작업에서 지킬 것

- 서버가 `cookingMethod`·`dishType`·`hashtags` 필드를 열면 **`recipe_tags.dart`를 지우고**
  응답 필드를 읽는다. 파서를 남긴 채 필드를 추가하면 두 출처가 갈라진다.
- 서버가 먼저 배포되면 구버전 앱에서는 태그 칩이 사라진다(설명은 정상). 기능이 깨지는 건
  아니지만 배포 순서를 알고 있을 것.
- 태그 값은 서버 시드가 정한다. 앱에 조리방법·요리종류 목록을 상수로 박지 않는다.
